# Плейлисты и журналы

## API плейлистов

**Конечная точка:** `GET /api/v1/playlist`

| Параметр | Тип    | Обязательный | Описание                                     |
| -------- | ------ | ------------ | -------------------------------------------- |
| `name`   | string | Нет          | Фильтрация результатов по наименованию медиа |

**Возвращает:** файл плейлиста в формате M3U (`Content-Type: application/x-mpegURL`)

Данная конечная точка отдает плейлист M3U, содержащий URL-адреса потоковой передачи для всех торрентов, сохраненных в TorrPlay, с возможностью фильтрации по имени. Это позволяет открыть всю библиотеку TorrPlay в любом медиаплеере с поддержкой формата M3U по одному URL.

### Формат ответа

```
#EXTM3U
#EXTINF:-1,Sintel
http://localhost:8090/api/v1/stream/08ada5a7a6183aae1e09d831df6748d566095a10?path=Sintel.mp4
```

Каждой записи `#EXTINF` соответствует URL-адрес потоковой передачи для указанного торрент-файла.

### Примеры использования

Открыть все торренты в VLC:

```sh
vlc "http://localhost:8090/api/v1/playlist"
```

Фильтрация плейлиста по имени:

```
GET /api/v1/playlist?name=Sintel
```

Сохранение плейлиста в файл:

```sh
curl -o torrplay.m3u http://localhost:8090/api/v1/playlist
```

### Аутентификация и совместимость с медиаплеерами

| Режим аутентификации | Доступ к конечным точкам потоковой передачи | Примечание                                                                                                    |
| -------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Отключена            | Без аутентификации                          | Учётные данные не требуются                                                                                   |
| Basic                | Без аутентификации                          | URL-адреса потоковой передачи доступны во всех плеерах без учётных данных                                     |
| Bearer               | Cookie-файл сессии                          | Потоковая передача защищена; браузерные плееры используют `HttpOnly` cookie-файл сессии, полученный при входе |

При использовании аутентификации типа **Bearer** конечные точки потоковой передачи доступны через cookie-файл сессии, который сохраняется в процессе авторизации. При использовании аутентификации типа **Basic** для конечных точек потоковой передачи не требуется аутентификация, что обеспечивает совместимость со всеми медиаплеерами.

## Просмотр журнала в оперативной памяти

**Конечная точка:** `GET /api/system/logs`

**Возвращает:** массив JSON с последними записями журнала

TorrPlay хранит последние записи журнала в кольцевом буфере в оперативной памяти, предоставляя удобный механизм просмотра актуальных событий приложения без необходимости прямого доступа к файловой системе. Этот подход особенно полезен при контейнерном развёртывании или когда прямой доступ к файлам журнала ограничен.

### Параметры хранения и настройка

| Параметр         | Значение по умолчанию | Максимум | Описание                                                                                                          |
| ---------------- | --------------------- | -------- | ----------------------------------------------------------------------------------------------------------------- |
| `log_store_size` | `100`                 | `1000`   | Количество записей журнала, удерживаемых в кольцевом буфере; значение `0` отключает хранение в оперативной памяти |
| `log_level`      | `INFO`                | —        | Минимальный уровень детализации журналирования (`DEBUG`, `INFO`, `WARN`, `ERROR`)                                 |
| `log_format`     | —                     | —        | Значение `json` включает структурированное журналирование в стандартный вывод                                     |

### Поля записи журнала

Каждый элемент возвращаемого массива JSON содержит следующие поля:

| Поле    | Тип    | Описание                                                                                                       |
| ------- | ------ | -------------------------------------------------------------------------------------------------------------- |
| `time`  | string | Временная метка события в формате ISO 8601                                                                     |
| `level` | string | Уровень записи журнала: `DEBUG`, `INFO`, `WARN` или `ERROR`                                                    |
| `msg`   | string | Текстовое описание события                                                                                     |
| `data`  | object | Необязательные структурированные данные в формате «ключ — значение»; поле отсутствует, если данные не переданы |

### Пример ответа

```json
[
  {
    "time": "2026-01-01T12:00:00Z",
    "level": "INFO",
    "msg": "stopping background downloader"
  },
  {
    "time": "2026-01-01T12:00:01Z",
    "level": "DEBUG",
    "msg": "streaming is active, pausing background downloader"
  }
]
```

### Настройка уровня детализации и объёма хранения

Для получения расширенного диагностического вывода следует установить параметр `log_level` в значение `DEBUG`:

```sh
curl -X PATCH http://localhost:8090/api/v1/settings \
  -H "Content-Type: application/json" \
  -d '{"log_level": "DEBUG", "log_store_size": 500}'
```

Включение структурированного журналирования в формате JSON в стандартный вывод (рекомендуется при агрегации журналов внешними средствами, такими как Loki или Fluentd):

```sh
curl -X PATCH http://localhost:8090/api/v1/settings \
  -H "Content-Type: application/json" \
  -d '{"log_format": "json"}'
```
