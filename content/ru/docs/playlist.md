## API плейлистов

**Эндпоинт:** `GET /api/v1/playlist`

| Параметр | Тип    | Обязательный | Описание                                     |
| -------- | ------ | ------------ | -------------------------------------------- |
| `name`   | string | Нет          | Фильтрация результатов по наименованию медиа |

**Возвращает:** плейлист в формате M3U (`Content-Type: application/x-mpegURL`)

Эндпоинт возвращает плейлист M3U со ссылками на потоки всех торрентов из библиотеки TorrPlay. Список можно фильтровать по названию. Это позволяет открыть всю библиотеку в любом внешнем медиаплеере по единой ссылке.

### Формат ответа

```
#EXTM3U
#EXTINF:-1,Sintel
http://localhost:8090/api/v1/stream/08ada5a7a6183aae1e09d831df6748d566095a10?path=Sintel.mp4
```

В каждой строке `#EXTINF` содержится ссылка на стрим конкретного файла.

### Примеры использования

Открыть все торренты в VLC:

```sh
vlc "http://localhost:8090/api/v1/playlist"
```

Фильтрация плейлиста по имени:

```
GET /api/v1/playlist?name=Sintel
```

Сохранение плейлиста в файл:

```sh
curl -o torrplay.m3u http://localhost:8090/api/v1/playlist
```

### Аутентификация и совместимость с медиаплеерами

При включённой аутентификации для получения плейлиста передайте токен воспроизведения:

```sh
vlc "http://localhost:8090/api/v1/playlist?token=tp_play_9f8a3c2e1b..."
```

Если запросить плейлист с параметром `?token=...`, TorrPlay автоматически добавит этот токен во все ссылки на видео внутри M3U-файла. Внешний плеер сможет сразу воспроизводить файлы без повторной авторизации. Подробнее о токенах читайте в руководстве по [Аутентификации](/docs/authentication/).

## Просмотр логов в оперативной памяти

**Эндпоинт:** `GET /api/system/logs`

**Возвращает:** массив JSON со свежими записями журнала

TorrPlay сохраняет последние логи в кольцевой буфер в оперативной памяти. Их можно просматривать через API без прямого доступа к файлам на диске, что особенно удобно при работе в Docker.

### Параметры хранения и настройка

| Параметр         | Значение по умолчанию | Максимум | Описание                                                                                                          |
| ---------------- | --------------------- | -------- | ----------------------------------------------------------------------------------------------------------------- |
| `log_store_size` | `100`                 | `1000`   | Количество записей журнала, удерживаемых в кольцевом буфере; значение `0` отключает хранение в оперативной памяти |
| `log_level`      | `INFO`                | —        | Минимальный уровень детализации журналирования (`DEBUG`, `INFO`, `WARN`, `ERROR`)                                 |
| `log_format`     | —                     | —        | Значение `json` включает структурированное журналирование в стандартный вывод                                     |

### Поля записи журнала

Каждый элемент возвращаемого массива JSON содержит следующие поля:

| Поле    | Тип    | Описание                                                                                                       |
| ------- | ------ | -------------------------------------------------------------------------------------------------------------- |
| `time`  | string | Временная метка события в формате ISO 8601                                                                     |
| `level` | string | Уровень записи журнала: `DEBUG`, `INFO`, `WARN` или `ERROR`                                                    |
| `msg`   | string | Текстовое описание события                                                                                     |
| `data`  | object | Необязательные структурированные данные в формате «ключ — значение»; поле отсутствует, если данные не переданы |

### Пример ответа

```json
[
  {
    "time": "2026-01-01T12:00:00Z",
    "level": "INFO",
    "msg": "stopping background downloader"
  },
  {
    "time": "2026-01-01T12:00:01Z",
    "level": "DEBUG",
    "msg": "streaming is active, pausing background downloader"
  }
]
```

### Настройка уровня детализации и объёма хранения

Для получения расширенного диагностического вывода следует установить параметр `log_level` в значение `DEBUG`:

```sh
curl -X PATCH http://localhost:8090/api/v1/settings \
  -H "Content-Type: application/json" \
  -d '{"log_level": "DEBUG", "log_store_size": 500}'
```

Включение структурированного журналирования в формате JSON в стандартный вывод (рекомендуется при агрегации журналов внешними средствами, такими как Loki или Fluentd):

```sh
curl -X PATCH http://localhost:8090/api/v1/settings \
  -H "Content-Type: application/json" \
  -d '{"log_format": "json"}'
```
