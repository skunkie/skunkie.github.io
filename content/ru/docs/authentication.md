# Аутентификация

TorrPlay обеспечивает защиту конечных точек API двумя методами аутентификации. Метод аутентификации можно настроить через конечную точку `/api/v1/settings`.

По умолчанию аутентификация **отключена**.

## Типы аутентификации

### Базовая аутентификация (`basic`)

Требует указания имени пользователя и пароля при каждом обращении к API. Данный метод применяется ко всем конечным точкам, **за исключением** конечных точек потоковой передачи (`/api/v1/stream/*`), что обеспечивает медиаплеерам возможность доступа к потокам без прохождения аутентификации.

### Аутентификация по токену Bearer (`bearer`)

Аутентификация на основе токенов JSON Web Tokens (JWT). Все конечные точки защищены, включая потоковую передачу (управляется через cookie-файл сессии).

## Включение аутентификации

TorrPlay поддерживает два типа аутентификации. Выберите тот, который подходит для вашего сценария:

{{< tabs "auth-type" >}}
{{< tab "Basic Auth" >}}

Имя пользователя и пароль передаются с каждым запросом через HTTP Basic Auth. Конечные точки потоковой передачи остаются незащищёнными для обеспечения совместимости с медиаплеерами.

{{< /tab >}}
{{< tab "Bearer Token Auth" >}}

Для аутентификации используются JWT-токены. Защите подлежат все конечные точки, включая потоковую передачу. Кроме того, для доступа из браузера устанавливается защищённый cookie-файл сессии с атрибутом `HttpOnly`.

### Активация базовой аутентификации

```sh
curl -X PATCH http://localhost:8090/api/v1/settings \
  -H "Content-Type: application/json" \
  -d '{
    "auth": {
      "enabled": true,
      "type": "basic",
      "username": "admin",
      "password": "your-password"
    }
  }'
```

### Активация аутентификации по токену Bearer

```sh
curl -X PATCH http://localhost:8090/api/v1/settings \
  -H "Content-Type: application/json" \
  -d '{
    "auth": {
      "enabled": true,
      "type": "bearer",
      "username": "admin",
      "password": "your-password"
    }
  }'
```

При включении аутентификации `bearer` автоматически генерируется и сохраняется секрет JWT.

## Получение токена (аутентификация Bearer)

Конечная точка `/oauth/token` **доступна только** при включённой аутентификации `bearer`:

```sh
curl -X POST http://localhost:8090/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=password&username=admin&password=your-password"
```

Ответ сервера:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer"
}
```

В браузере также устанавливается защищённый cookie-файл сессии с атрибутом `HttpOnly`.

## Выполнение запросов с аутентификацией

### С токеном Bearer

Добавьте JWT-токен в заголовок `Authorization` каждого запроса:

```sh
curl -H "Authorization: Bearer your-jwt-token" http://localhost:8090/api/v1/torrents
```

### С базовой аутентификацией

Используйте флаг `-u` для curl, чтобы передать имя пользователя и пароль:

```sh
curl -u admin:your-password http://localhost:8090/api/v1/torrents
```

### Аутентификация по cookie (Bearer)

При использовании аутентификации типа `bearer` в браузере cookie-файл сессии, полученный от конечной точки `/oauth/token`, автоматически передаётся в составе запросов к конечным точкам потоковой передачи. Атрибут `HttpOnly` данного cookie-файла предотвращает доступ к нему через XSS-атаки.

## Восстановление доступа: отключение аутентификации

Если вы забыли учётные данные, временно отключите аутентификацию:

```sh
TORRPLAY_DISABLE_AUTH=true ./torrplay --data-dir=./data
```

Это позволяет получить доступ к API без учётных данных. Сбросьте настройки через API, затем удалите переменную окружения и выполните перезапуск.
